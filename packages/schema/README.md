# Schema 0.2.0

The TypeScript transport contract follows the P0a plan and section 4 of the AI 3D upgrade v1.1. `parseAnalysis` accepts complete `0.1.0` and `0.2.0` records; it validates historical records without relabeling them. `parseLegacyAnalysis` additionally requires `0.1.0`. New writes use `SCHEMA_VERSION = '0.2.0'`. `parseAnalysis`, `parsePose3DResult` and `parseVideoAsset` throw readable errors; their corresponding `validate*` type guards return a boolean. Unknown additive fields are tolerated. Unsupported versions are rejected. `pipelineVersion` identifies algorithm changes; each metric carries a separate `definitionVersion`.

`validateSkeletonData` checks binary lengths, finite increasing capture timestamps, normalized coordinates, and confidence ranges. Float32 files use little-endian encoding. Missing coordinates are NaN with confidence 0. JSON never carries NaN values. `CWB_65` provides the index mapping with the face landmarks removed.

`Analysis.pose3d` is optional and is only accepted on a successful v0.2 2D analysis with a matching skeleton frame count. It never changes `skeleton`, the original five metrics, or their units. Model IDs, runtime pairs, SHA-256 provenance, root/axis/unit conventions, window bounds and quality ratios are validated independently. Only a successful 3D task can carry `keypointsKey`; failures require `errorCode`. Unconfigured models should return an API error instead of inventing a model hash for a result.

`validatePose3DBuffer(bytes, result)` decodes little-endian `[frameCount, 65, 4]` bytes and returns a `Float32Array`. It supports unaligned Buffer/typed-array subviews. `validatePose3DData(points, result)` validates already-decoded values. Missing 3D points must be exactly `[NaN, NaN, NaN, 0]`; valid points require finite XYZ and confidence in `(0, 1]`. Data outside windows and in blocked windows is rejected. Reported coverage must match the binary, and window usability cannot exceed frames with any data. These are transport checks, not model accuracy or anatomical quality validation. Filesystem containment and provenance sidecar validation remain gateway responsibilities.

Populated frames require both hips with an XYZ midpoint within `1e-5` of zero, matching the Python root-relative boundary. Overall usability cannot exceed covered frames divided by the number of frames in unblocked windows; empty or fully blocked windows must have zero usability.

Production results should persist immutable original input, model/version metadata and binaries. Re-analysis creates a new analysis ID rather than overwriting old results. Worker/gateway transport errors must become an explicit failed task.
